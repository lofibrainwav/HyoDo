# HyoDo 4.20.0 Release Notes

## Intent

Publish participant-preserving graph views and opt-in, evidence-linked intent
comparisons from PR #429. Hosts supply the requirements, values, and references;
HyoDo validates and compares them without claiming semantic intent extraction.

## Boundaries

- Existing event records are not rewritten.
- Missing evidence, inferred requirements, projections, and changed requirements
  without a new intent source remain unobserved.
- Occurrence, observation, and recording timestamps are not separately stored.
  The broader temporal event contract remains a design target.
- Artifact references do not independently prove artifact contents or full
  fulfillment of user intent. Hosts own retention, retrieval, and extraction.
- Source, published package, served runtime, and human authority remain distinct.

## Validation

The release candidate passed public package verification: 1,762 tests passed
and one was skipped, followed by lint, formatting, type checks, distribution
build/install, and CLI smoke checks. Main CI and installation smoke passed for
the tagged commit. Publication provenance and clean installed-package readback
passed; the release chain below records the exact evidence.
The separately measured live HyoDo board reports 4.20.0 and the tagged source
commit. This does not promote unrelated host integrations to observed success.

## Rollback

If post-publication verification fails, preserve the tag and evidence and assess
whether to yank the release. Already installed environments require an explicit
reinstall of the chosen previous version; yanking does not downgrade them.
