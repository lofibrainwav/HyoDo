# HyoDo 4.14.0 Release Notes

## Intent

The 4.14.0 development cycle closes out Phase 1 of the HyoDo Agent OS design
(packages 1-A through 1-E): test integrity, the local evidence-graph viewer,
`hyodo connect`, audience profiles, and the M5-A/M5-B remote-connector and
local-bridge contracts, carried forward from the v4.13.0 policy-ASK and
trust-ladder baseline. The release chain below has been completed; each box
is a measured receipt.

## Included changes

- Test integrity (Phase 1-E): `hyodo check` runs a native, model-free AST
  scan of the project's own tests, reporting vacuous-test counts and failing
  the Truth gate under `--strict-tests` when they are found.
- Widened credential-shaped URL detection for `.aws/`, `.ssh/`, `.netrc`,
  `.kube/`, credential and secret-shaped path and query markers.
- Local evidence-graph viewer: `hyodo dashboard` serves `GET /graph`
  (server-rendered five-column virtue layout plus the core-engine-pulse orb)
  and `GET /api/graph` (live `hyodo.evidence-graph/v1` JSON).
- `hyodo connect` (Phase 1-D): dry-run-by-default harness wiring for Claude
  Code hooks, `pre-commit`, and GitHub Actions, plus `--shadow` mode and
  `--status` drift reporting; `cursor`/`codex` report UNOBSERVED.
- M5-B local bridge: an untracked pairing lifecycle
  (`hyodo mcp pair`/`unpair`/`revoke`/`pairing show`) and a `--paired` option
  on `hyodo mcp serve` that verifies the caller's bearer token on every
  request; remote `availability` stays `UNOBSERVED`.
- Audience profiles (`--audience vibe|engineer|professional`) on `check`,
  `safe`, `policy check`, and `event record --policy`: presentation wording
  only, with decisions, exit codes, and evidence references staying
  byte-identical across profiles.
- Surfaced trust level 2+ ledger obligations and recording outcomes in CLI
  receipts.
