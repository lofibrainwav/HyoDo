# HyoDo 4.21.6 Release Notes

## Intent

Ship the deployed-runtime gap closed by #477 that the 4.21.5 release itself
did not carry: the retired-reader registration GC and the two-state release
candidate planning fix. This is the final maintenance release before freeze.

## What ships

- Retired-reader registration GC (`prune_retired_registrations`): before a new
  MCP reader registers, startup GC removes records whose PID/process-start
  identity is provably retired (SIGTERM, SIGKILL, crash, reboot residue). An
  unobservable process identity is never treated as dead.
- Release candidate planning accepts both coherent states (`UNPREPARED` and
  `PREPARED`) instead of rejecting a fully prepared candidate.

## Honest deployment status of these fixes in 4.21.5

At the time 4.21.5 shipped, both fixes existed only on `main` (PR #477,
merged as 191580419b1ae2fdc40cfa6a3a5895b7e54c1e39). The installed PyPI wheel
(4.21.5), the pipx install, and the KINGDOM runtime board
`board-20260923-4.21.5 @ 1743690` were all verified to NOT contain
`prune_retired_registrations`. Residue from an unclean reader exit therefore
re-accumulated in 4.21.5 deployments; it was cleaned manually from merged
source, which is not the same as a deployed fix. This release closes that gap
for real: global install and promoted runtime both pick up the GC when 4.21.6
is released and promoted.

## Verification already measured on the merged source

- 31/31 focused tests (`tests/test_release_plan.py`,
  `tests/test_mcp_readers.py`) PASS on Python 3.14.7.
- Crash-residue pruning measured live: a SIGKILLed reader's registration is
  removed by the next reader's startup GC; SIGTERM residue likewise; reused
  PIDs are pruned; unobservable identities are kept.
- `ruff check`, `ruff format --check`, `pyright`: 0 errors.
- `scripts/verify-public.sh` PASS on merged main.
