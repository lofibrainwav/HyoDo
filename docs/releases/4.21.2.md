# HyoDo 4.21.2 Release Notes

## Intent

Close measured verification-plumbing blind spots without changing the HyoDo 4.21
status or exit-code contracts. This patch makes the documented public verifier work
from a standard pipless uv environment, bounds test-integrity language to what its
AST heuristic can prove, distinguishes file-cap gaps from non-text/binary safety
gaps, and makes an unchanged release-chain readback zero-write. It also closes two
enforcement gaps found by adversarial review: the built-artifact description check
now runs in public verification instead of always skipping, and the public-language
gate rejects bare virtue-syllable prose and requires the canonical trilingual label
form instead of allowing the six syllables anywhere. A complete label mentioned
inside an English sentence remains allowed label usage, not Korean prose. The same
rule now also applies to commit messages and
PR text: the CI job calls the shared predicate instead of its own copy of the old
rule. Check status, coverage, and exit-code semantics are unchanged.

## Outcome: incomplete immutable release, not published to PyPI

The v4.21.2 GitHub Release was published by hand before its SBOM evidence was
attached. This repository uses immutable releases, so the published Release
could not take the assets afterwards. Both downstream gates failed closed:

- Release evidence run `35782458730` refused to mutate a published Release that
  lacked the SBOM assets.
- Publish run `35782446574` refused the PyPI upload because the Release carried
  no SBOM; the publish and readback jobs were skipped.

Nothing reached PyPI. The tag and Release are kept unchanged as the historical
record of this chain; they are not deleted or reused.

Root cause is an orchestration defect, not only an operator slip: the release
pipeline owned candidate intake through merge, while tag, draft Release,
evidence, publication, and PyPI were manual steps outside any state machine.
No gate owned the one irreversible step, publishing the Release.
