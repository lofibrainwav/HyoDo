# HyoDo 4.16.0 Release Notes

## Intent

The 4.16.0 cycle tightens the honesty of what HyoDo's decisions claim to have
observed. `hyodo check` derives a real Benevolence signal from onboarding
evidence instead of reporting it `UNOBSERVED`, and `hyodo score --from-check`
derives all five HyoDo Integrity Score pillar inputs from measured
`check`/`safe`/test-integrity output rather than requiring the caller to
guess floats. Shadow mode's documented "always exits 0, nothing is blocked"
guarantee now holds on every early exit, `hyodo connect claude-code`
bootstraps a starter policy automatically, `hyodo safe` reports its scan
scope and coverage explicitly, the gitleaks and trufflehog adapters gain
positive controls against silent CLI drift, and `hyodo mcp continuity`
counts hook-recorded actors as their own hosts so a hook-only onboarding can
reach `OBSERVED`/`READY`. Each box below is a measured receipt.

## Included changes

- `hyodo check` emits three onboarding/developer-experience signals
  (`readme_present`, `start_hint_present`, `help_text_present`) via
  `hyodo/dx_signals.py::collect_dx_signals`, printed as an advisory
  Benevolence `dx-signals` row and included under `dx_signals` in `--json`;
  `hyodo score --from-check` now derives Benevolence from this evidence
  instead of reporting it `UNOBSERVED`.
- `hyodo score --from-check [--root R] [--json]`: derives the five HyoDo
  Integrity Score pillar inputs in-process from `hyodo check`/`hyodo
  safe`/the test-integrity scan, with a literal `PILLAR_RULE_TABLE` and an
  `OBSERVED`/`PARTIAL`/`UNOBSERVED` coverage state per pillar (an
  `UNOBSERVED` pillar reports `None`, never a smuggled 0 or 100, and is
  excluded from the Eternity geometric mean). Explicit flags still override
  one derived pillar, recorded as `override: true`.
- `hyodo connect claude-code` bootstraps a permissive starter
  `.hyodo/policy.toml` when none exists (dry run prints, `--write` creates
  and tracks its digest for `--status` drift); an existing policy file is
  never overwritten.
- `hyodo safe` (`--json` and text) reports `scope` and `coverage` alongside
  `source`, plus a hint to pass a directory when the scope is `diff` or
  `status`.
- `hyodo policy check --shadow` and `hyodo event record --shadow` no longer
  exit 2 on a missing/invalid policy, an unmappable hook payload, or a
  failed ledger append — every early exit is now `[SHADOW, not blocking]`
  and, where possible, recorded as `policy.shadow: true` /
  `policy.decision: "UNOBSERVED"`. A missing policy under `--hook
  claude-code` (shadow or not) now evaluates against the same permissive
  all-defaults policy other commands fall back to and is recorded instead
  of crashing.
- `hyodo mcp continuity` no longer reports `status: READY` on an empty
  workspace: `hyodo.continuity/v1` separates `integrity_status` from
  `coverage_status`, and now counts hook-recorded actors
  (`.hyodo/agent-events.jsonl` events with `actor: "agent"` and a non-empty
  `actor_id`) as their own hosts (`source: "hook"`), with a `by_source`
  breakdown and an always-present `notes` array distinct from `reasons`.
- `hyodo safe --scan gitleaks`: fixed the removed `--format` flag (gitleaks
  8.x exited 126); added a `version` positive control.
- `hyodo safe --scan trufflehog`: added the same `--version` positive
  control as gitleaks, so a CLI-drifted binary that exits 0 with unrelated
  output is caught instead of reported clean.
