# HyoDo 4.13.0 Release Notes

## Intent

The 4.13.0 development cycle carries the policy ASK and trust-ladder feature,
public score identity, and workflow naming forward from the v4.12.0
release-trust baseline. This document is preparation only; no tag, GitHub
Release, or PyPI publication is performed by this change.

## Included changes

- Policy evaluation can return `ASK` for observed external variables that need
  an operator decision.
- Trust caps and explicit operator grants are exposed through
  `hyodo policy trust grant|show`.
- Policy exit codes are explicit: `ALLOW=0`, `DENY=1`, `UNOBSERVED=2`, and
  `ASK=3`.
- Release preparation validates and updates all seven version-bearing sources
  as one operation.
- The roadmap and public policy documentation now describe the live ASK path.
- The public score is named **HyoDo Integrity Score**, using the
  **Six-Virtue Model** and **Trinity Gates** subset.
- **HYOGOOK V5** remains the formula lineage, while the GitHub required check
  context is named **HyoDo Integrity Score**.
