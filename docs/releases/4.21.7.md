# HyoDo 4.21.7 Release Notes

## Intent

Close the checkout-controlled authority class: HyoDo read operator decisions
(gate approvals, policy trust, pairing, scan exceptions) and ledger history
from inside the checkout it was verifying, so a repository could supply its
own authority. 4.21.7 moves that state to per-user storage bound to the
workspace path, makes `hyodo safe` and sampled `hyodo check` report what they
actually observed, and adds a hostile-clone gauntlet as a required release
gate. Security-only; no new capability. Supersedes 4.21.6, which was never
published to PyPI. Contract and upgrade notes:
[`docs/TRUST_BOUNDARY.md`](../TRUST_BOUNDARY.md).

## Verification measured before release

- Hostile-clone gauntlet: 10/10 PASS on the wheel built from the fix; the
  published 4.21.5 wheel fails it (exit 1).
- Full suite on the fix: 2027 passed, 2 skipped; ruff and pyright clean.
- Independent judge in a separate detached worktree: three rounds, final
  GREEN, with guards reverted in a scratch copy to show the tests bite.
