# HyoDo 4.18.0 Release Notes

## Intent

HyoDo 4.18.0 is the release-candidate line for the next real-execution
measurement step. It keeps HyoDo as an observation and evidence spine while
making two boundaries explicit: sampled checks must disclose their limited
scope, and external orchestration can be measured through a read-only sidecar
without moving scheduling or execution authority into HyoDo.

## Included changes

- `hyodo check` reports the bounded sampled-syntax limitation in normal,
  `--quiet`, and `--json` output. BYOG gates still take precedence.
- Public verification builds into an isolated temporary directory and tests a
  wheel in a clean virtual environment. The verifier tolerates a missing
  `TMPDIR` parent instead of failing before the package build.
- `hyodo.orchestration-observation/v1` validates serial/parallel topology,
  dependency joins, attempts, approval waits, explicit intervention and
  unresolved-observation counters, and evidence references.
- `hyodo.friction-event/v0` deterministically derives measurement records for
  retries, waits, rework, human intervention, verification failure, blocked
  actions, and unresolved claims. Every derived record starts with
  `friction.class = unknown`.
- The observation adapter does not schedule work, grant execution authority,
  override policy, override an evidence gate, or infer intent from raw prompts.

## Measurement handoff

After the release chain is complete, install the published 4.18.0 artifact in
the target KINGDOM measurement environment, freeze the exact HyoDo and KINGDOM
SHAs, run Measured Run #3, and attach its receipt to Evidence Pack v1. The
receipt must mark each requested signal as observed, partial, or unobserved;
the sidecar contract must not be treated as proof that a signal occurred.
