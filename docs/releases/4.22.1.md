# HyoDo 4.22.1 Release Notes

## Intent

Correctness and diagnostics release on top of 4.22.0. It makes two error
surfaces actionable without changing any machine semantics (#516, #508) and
reconciles public version wording with the published package (#532).
Feature development is frozen; this is correctness maintenance only.

The immutable 4.22.0 package predates #535. This document describes the
4.22.1 candidate.

## Candidate boundary

- Source baseline: `747413fdb4a7bd22b4c15df15a5e8bce13ffcea7` (#535).
- Policy: `policy_invalid` stays the stable reason code and exit 2 stays
  `UNOBSERVED`; the validation detail is a separate field and human line.
- Eval: an invalid dataset id stays `UNOBSERVED` with exit 2; the message now
  names the rejected value (bounded to 60 characters), its type, and the
  accepted shape. Nothing is repaired.
- No dependency, authority, or product-boundary change.
